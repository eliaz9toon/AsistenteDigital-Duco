# Duco Asiste — avance técnico del 28-10-2026

## Base existente (recibida)
- Sitio web local `duoc.html` con módulos `js/` y estilos `css/`.
- Cliente de Ollama (`js/ollama-client.js`), con endpoint local `/api/chat`.
- Historial temporal mediante Session Storage (`js/chat-handler.js`).
- Sistema de navegación y resaltado. La verificación manual en navegador sigue pendiente.

## Cambios incluidos en esta versión
1. Botón «Nueva conversación» para limpiar el historial de sesión, restablecer el chat y volver a mostrar bienvenida.
2. Bloqueo de envíos simultáneos mientras se procesa una respuesta para evitar mensajes desordenados.
3. Límite de 2000 caracteres por pregunta para evitar entradas accidentales excesivas.
4. Verificación de disponibilidad de Ollama en cada consulta (el anterior estado offline no quedará permanentemente almacenado).
5. Versionado de recursos CSS/JS modificados para invalidar caché.
6. Pruebas automáticas de humo `tests/smoke-test.js`, que verifican historial y reconexión simulada.

## Cómo ejecutar localmente
Desde la carpeta donde está `duoc.html`:

```bash
python -m http.server 5500
```

Abrir http://127.0.0.1:5500/duoc.html en el navegador. Ollama debe estar instalado y activo en http://localhost:11434 y disponer del modelo configurado en `duoc.html` (actualmente `qwen3.5:9b`).

Prueba automática independiente:

```bash
node tests/smoke-test.js
```

## Base de datos
El modelo propuesto de Oracle (30 tablas; hoy el modelo implementado tiene 32, ver `database/README.md`) se incorporó desde el paquete recibido. `database/oracle/schema.sql` contiene el DDL Oracle con claves identity para los identificadores simples; `database/oracle/create_user.sql` prepara un esquema local `DUCO_APP`. `admin-app/` incluye un backend local con `python-oracledb` y una interfaz CRUD para administrar las tablas. Las instrucciones están en `database/README.md` y `admin-app/README.md`.

La instancia Oracle no pudo instalarse ni iniciarse en el entorno de trabajo, por lo que el esquema y la aplicación todavía requieren conexión y validación contra Oracle XE/Free. El chatbot web sigue guardando conversaciones en Session Storage; aún no envía los mensajes del chat al esquema Oracle.
